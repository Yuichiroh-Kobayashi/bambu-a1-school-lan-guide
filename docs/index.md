3Dプリンタを購入し、電源を入れれば授業が始まる。

そう考えたくなります。

しかし、実際に最初に止まったのは造形ではありませんでした。止まったのは、その手前の4か所です。

- 3DプリンタのWi-Fi接続
- ファームウェア（3Dプリンタを制御するソフトウェア）の更新
- スライサー（3Dモデルを3Dプリンタで造形できるデータへ変換するソフトウェア）の初期設定
- 利用者ごとの設定展開

この記事は、学校へBambu Lab A1 miniを複数台導入し、多数の利用者が共用できる状態へ整えるまでの初年度記録です。生徒をBambu Labのクラウドアカウントへログインさせず、校内ネットワークから3Dプリンタへ接続するLANモードを中心に扱います。

## 初年度に確認できたことと、できていないこと

A1 miniを6台使用し、中学校3年生4クラス（1クラス約40人、計約160人）を対象に、3Dモデルの作成から造形までの一連の工程を授業として実施しました。ただし、そこへ至るまでには何度も止まっています。WPA3-onlyのSSIDへは接続できず、納入時のファームウェアではLANモードのアクセスコードを追加できず、PC教室の端末はBambu Studioのネットワークプラグインを取得できませんでした。

止まったのは造形機構ではありません。ネットワーク、ファームウェア、Bambu Studioの設定、Windowsのユーザー設定という、機器と周辺環境の接続部分でした。なかでも尾を引いているのが、多数の生徒用Windowsユーザープロファイルへ同じ初期状態を展開する公式手順を、本記事の執筆時点では確認できていないことです。本事例では非公式な設定展開で補いました。この点が残る限り、次年度以降の継続と、担当者が変わったときの移管は保証できません。

導入前に確認しておく条件は「[導入前に確認する条件](#preflight-check)」に、根拠の区分と限界は「[記述の区分と限界](#evidence-levels)」にまとめています。

単一校・単一年度の環境で得た事例であり、一般的な有効性を検証したものではありません。新たにBambu Lab製3Dプリンタを導入する学校やFabLabが、自校の条件を確認するための材料として整理しました。

## 1. この記事の対象

本記事の主な対象読者は、学校やFabLabなどで、Bambu Lab製3Dプリンタを多数の利用者が共用する環境を整える担当者です。

特に想定しているのは、次の担当者です。

- 授業担当者
- ICT・情報教育担当者
- ICT支援員・実習助手
- 学校管理職、教育委員会・学校法人の導入担当者
- FabLabや研修施設の施設管理者
- 販売・導入支援事業者

必要な節へは、冒頭の「読者別の参照先」から移動できます。

公開記事であるため、学校名、ネットワーク構成、設定値、認証情報、内部手順は扱いません。端末数と機器台数は、授業規模と運用条件を説明するために必要な範囲で記載します。

ここで示すのは、ある公立中学校の制約下で初年度に実施できた一つの事例です。この構成が、他校で同じ結果をもたらすことを示すものではありません。

また、この記事は、導入済みの3Dプリンタを授業で操作するための日常マニュアルではありません。初年度の授業時数、造形時間、停止要因、教員の授業外作業は、[初年度の授業実践](classroom-practice-2025.md)に分けて記録しています。

## 2. 記述の区分と限界

本記事では、根拠の異なる情報を次のように区分します。

- **公式資料**：メーカーが公開した仕様や手順
- **本事例の環境**：本記事の導入環境で確認した結果
- **他校事例**：別の学校環境から提供された確認結果
- **本事例で採用した判断**：確認結果と制約を踏まえて選んだ方法
- **未確認**：候補として挙げるが、実機または授業で検証していない事項

本記事で確認できたのは、導入初年度に一連の工程を実施できたことです。次の段階は分けて扱います。

| 段階 | 本記事での意味 | 本記事執筆時点の扱い |
|---|---|---|
| 初年度の実施 | 当該年度に、モデル作成から造形までを全クラスで実施できる | 確認済み |
| 反復可能性 | 同じ担当者と環境で、同じ手順を再実施できる | 改善を加えて再検証する段階 |
| 持続可能性 | 教員の授業外作業を含めても継続できる | 未確認 |
| 移管可能性 | 担当者が変わっても手順を引き継げる | 未確認 |

したがって、初年度に授業を実施できたことを、長期的・組織的な運用が完成したこととは扱いません。また、これは教育的成果の評価基準ではありません。

<a id="system-design"></a>
## 3. 3Dプリンタの導入に必要な設計

学校へ3Dプリンタを置くだけでは、授業利用は始まりません。

少なくとも、次の環境を設計する必要があります。

- 利用者が3Dモデルを作成する端末とソフトウェアの選定
- 3Dモデルを造形用データへ変換するスライサー（本事例ではBambu Studio）の設定
- Bambu Studioを利用するスライサー用PCへのユーザー設定
- 利用者端末からスライサー用PCへ3Dモデルを渡す方法
- スライサー用PCと3Dプリンタ間のネットワーク接続
- 造形順序・材料・安全・保守の管理
- ソフトウェアとファームウェアの更新方法
- 担当者が異動した場合の引継ぎ

学校で問題になりやすいのは、3Dプリンタ本体の性能ではありません。「誰が設定し、誰が保守し、誰がトラブルへ対応するのか」が決まらないまま、機器だけが納入されることです。

導入後に授業担当者個人へ運用が集中しないよう、体制を先に設計する必要があります。

不明な事項を、導入後に授業担当者だけへ委ねないでください。ICT・情報教育担当者、ICT支援員・実習助手、教育委員会や学校法人の情報担当者、販売事業者、実践経験のある教員と役割を分け、構成を検討します。

<a id="device-configuration"></a>
## 4. 導入時の構想と初年度の端末構成

### 当初はiPadとWindows PCの役割分担を想定

2025年夏の導入検討時には、生徒用iPadで3Dモデルを作成し、PC教室のWindows PC上のBambu Studioでスライスする構成を想定していました。

```text
生徒用iPad
  3Dモデルを作成
        ↓
Windows PC
  Bambu Studioでスライス
        ↓
Bambu Lab A1 mini
  LANモードで造形データを送信
```

しかし、初年度の授業開始時点では、端末をまたぐ次の運用検証が十分ではありませんでした。

- iPadからの3Dモデル書き出し
- 書き出した3Dモデルの保存場所の確認
- 同じ作品を複数回書き出した場合の版管理
- 修正前と修正後の3Dモデルの識別
- Windows PC側での受け取り
- Bambu Studioへの読み込み
- 提出に失敗した場合の復旧

そこで初年度は、データ移動に伴う不確定要素を減らすため、Tinkercadによる3Dモデル作成からBambu Studioでのスライスまでを、Windows端末40台を備えたPC教室で行いました。

初年度に行った工程は次のとおりです。

1. Tinkercadへログインする
2. 3Dモデルを作成する
3. 3Dモデルを、表面形状を保存するSTL形式のファイルとして書き出す
4. Bambu Studioへ読み込む
5. スライス結果を確認する
6. LANモードでBambu StudioとA1 miniを接続する
7. 送信先を確認して造形データを送る

iPadからWindows PCへデータを渡す一連の授業運用は、現時点では未確認です。

PC教室を持たない学校で、3Dプリンタとスライサー用PCを組み合わせて導入する場合は、生徒用端末からスライサー用PCまでのデータ経路を、購入前に検証する必要があります。

その経路が未設計のままでは、授業担当者が生徒のファイルを一件ずつ回収し、移動させる運用になりかねません。

<a id="modeling-environment"></a>
## 5. 3Dモデリング環境は、保存と復旧まで含めて選ぶ

初年度は、短時間で文字編集へ入りやすく、テンプレート配布とクラス管理ができるTinkercadを採用しました。

3Dモデリング環境は、形を作れることだけでは選べません。利用端末、初回設定、作品の保存場所、別端末での継続、教員による確認と救出、STLなどの受け渡しまで含めて選ぶ必要があります。

Tinkercad、Onshape、Shapr3D、国内の教育用CAD、Blenderの比較は、[学校の3Dモデリング環境をどう選ぶか](3d-modeling-environment-selection.md)にまとめています。

<a id="preflight-check"></a>
## 6. 導入前に確認する条件

導入前の確認事項は、根拠ごとに分けて整理します。

### 公式資料で確認する事項

- 対応するWi-Fi周波数帯
- 対応するネットワーク設定方法
- ファームウェア更新方法
- Bambu Studioの対応OSと動作条件
- 使用する材料と安全上の注意
- AMS Liteなど周辺機器の接続条件

### 本事例で必要だった事項

- A1 miniが接続可能なWi-Fiネットワーク
- Bambu Studioを実行できるWindows PC
- 生徒ごとのWindowsユーザープロファイル
- Windows PCからA1 miniへのLAN通信経路
- ネットワークプラグインの事前準備
- ファームウェアを更新できる経路
- 生徒用アカウントでの起動確認
- 生徒が作成したモデルをBambu Studioへ渡す方法

### 他校事例から得た注意

- ステルスSSIDでは、microSDカードによるWi-Fi設定が必要になる場合がある
- A1シリーズ本体とAMS Liteのファームウェアの組み合わせによっては、納入直後にAMS Liteを利用できない場合がある

### 推奨事項

- 納品前に本体と周辺機器のファームウェアを確認する
- 実際の生徒用端末と学校ネットワークで動作確認する
- 1台の検証用PCと検証用ユーザーで更新を先行確認する
- 消耗品と交換部品を継続的に調達できるようにする
- 安全管理、保守、障害対応の担当者を決める
- 担当者変更後の引継ぎ方法を準備する

<a id="printer-selection"></a>
## 7. Bambu Lab A1 miniを選んだ理由

A1 miniを選んだ主な理由は、学校予算の範囲で複数台をそろえられる価格帯だったことと、造形速度が速く、授業での待ち時間を抑えやすいことです。

光造形方式も検討しましたが、未硬化樹脂の取扱い、洗浄、二次硬化、周辺の清掃、廃液管理を授業運用へ組み込む必要があります。本事例の設備と監督体制では、その工程を安定して扱うことが難しいと判断し、採用しませんでした。

多数の生徒が扱う環境で、材料の取扱いと後処理の負担を抑えやすいことが、熱溶解積層方式を選ぶ決め手でした。フィラメントを溶かして積み上げるこの方式は、FFF（Fused Filament Fabrication、フィラメント溶解製法）と呼ばれます。FDMという呼称も広く使われていますが、こちらはStratasysの登録商標です。

3Dプリンタを教材として使う際には、完成品だけでなく、造形中の機構と積層過程を見せられることも選定時に重視しました。

A1 miniはオープン構造です。ヘッドの動き、X軸ベルト、Z軸送りねじ、造形物が積み上がる過程を複数方向から観察でき、機械がどのように形を作っているのかを生徒へ見せやすい構造でした。

一方で、オープン構造は、動作部や高温部へ近づける構造でもあります。価格や速度だけでなく、授業中と授業間の監督体制まで含めて選定する必要があります。

<a id="wifi"></a>
## 8. 購入前に確認するWi-Fi条件

### 公式仕様

A1 miniを学校やFabLabへ導入する前に、2.4 GHz帯のWi-Fiアクセスポイントを用意できるか確認してください。

公式仕様では、A1 miniのWi-Fi周波数範囲は2.4 GHz帯とされています。5 GHz帯のみのSSIDには接続できません。

詳細は[参考資料](references.md)に公式仕様へのリンクを掲載しています。

### 本事例で確認したこと

学校や施設では、端末用SSIDが5 GHz帯中心だったり、セキュリティ方針によってWPA3-onlyになっていたりする場合があります。

本事例の検証環境では、WPA3-onlyのSSIDへ接続できず、WPA2-Personalへ変更する必要がありました。

ただし、公式資料で「A1 miniはWPA3に対応しない」と明示した記述は確認できていません。そのため、WPA3非対応とは断定せず、本事例で確認された結果として扱います。

### 推奨

WPA2とWPA3の混在モードは、アクセスポイント、ファームウェア、設定の組み合わせによって挙動が変わる可能性があります。

施設のネットワーク管理者と協議し、2.4 GHz帯で実機が接続できるネットワークを、既存の情報セキュリティ方針に適合する形で用意します。本事例ではWPA2-Personalを使用しましたが、これを学校一般への推奨構成とはしません。

3DプリンタがWi-Fiへ接続できても、LANモードが使えるとは限りません。

Bambu Studioを実行するWindows PCから、A1 miniへLAN接続できる必要があります。アクセスポイントのクライアント隔離、プライバシーセパレータ、VLAN、ファイアウォールによって、端末間通信が遮断されていないか確認します。

Windows PC側は必ずしも3Dプリンタと同じSSIDへ接続する必要はありません。通信を許可された経路から3Dプリンタへ到達できれば構いません。

### ステルスSSIDへの接続

Bambu Labの公式Wikiでは、P1シリーズとA1シリーズについて、microSDカードを使ってWi-Fi設定を読み込ませる方法が案内されています。

この方法は、次の場合に利用できます。

- 接続先がステルスSSIDで、3Dプリンタ画面の一覧に表示されない
- Wi-Fiパスワードに、3Dプリンタ画面から入力できない文字が含まれる

`user_wifi.cfg`という設定ファイルを作成し、SSIDとパスワードを記述します。作成したファイルをmicroSDカードのルートディレクトリへ配置し、カードをmicroSDスロットへ挿入して再起動します。

3Dプリンタは起動時に設定ファイルを読み込みます。

他校での確認事例として、この方法によるステルスSSIDへの接続が成立しています。

ただし、設定ファイルにはSSIDとWi-Fiパスワードが可読状態で記録されます。設定に使用するmicroSDカードの管理、設定後のファイル削除、認証情報を含むファイルの保管と廃棄について、施設内の運用を定める必要があります。

<a id="lan-mode"></a>
## 9. LANモードを選んだ理由

LANモードを選んだ主な理由は、生徒ごとのBambu Labクラウドアカウントを運用せずに済むことです。Bambu StudioからA1 miniへの接続と造形データ送信を、校内LAN内で完結させられます。

LANモードでは、3Dプリンタ本体の画面にIPアドレスとアクセスコードが表示されます。造形前に使用する3Dプリンタの画面を確認し、Bambu Studioへ入力する運用としました。

LANモードによってローカル化できるのは、主としてBambu StudioからA1 miniへの接続と造形データ送信です。

次まで含めた授業環境全体が、クラウド非依存になるわけではありません。

- Bambu Studioの取得と更新
- ネットワークプラグインの取得
- ファームウェア更新
- Tinkercadによるモデル作成
- Google Classroomによる課題配信と提出

本事例では、固定IPアドレスやDHCP予約を利用できない制約があったため、使用時に本体画面の情報を確認する方式を採りました。授業時間内で、使用する3Dプリンタと送信先を照合できることを優先しています。

### 集中管理と手動接続

複数台の3Dプリンタを導入する場合は、集中管理方式も選択肢になります。

一方、本事例では、利用者が使用する3Dプリンタを選び、本体の状態と送信先を確認してから造形する手動接続を採用しました。

IPアドレスの入力そのものは主な学習目標ではありません。手動入力はインフラ上の制約から採用した操作であり、本体画面とBambu Studioの送信先を照合して誤送信を防ぐことを運用上の目的としました。ネットワーク上の機器がアドレスで識別されることを見る機会にはなりましたが、これは副次的な扱いです。

手動接続が常に適しているわけではありません。3Dプリンタ台数、造形件数、授業の学習目標によっては、集中管理方式の方が適する場合があります。

本事例では集中管理方式を検証していないため、具体的な比較や推奨は行いません。

<a id="firmware"></a>
## 10. ファームウェアの確認と更新

### 本事例で観察したこと

導入時のA1 miniのファームウェアは`v01.03.00.00`、Bambu Studioは`v02.04.00.70`でした。

この組み合わせでLANモードのアクセスコード追加を試みたところ、正常に完了しませんでした。

さらに、校内LAN経由でファームウェアを更新しようとした際、A1 miniの本体画面にダウンロードへ失敗した旨の表示が出て、更新を完了できませんでした。

### 当時の制約

納入時のファームウェア`v01.03.00.00`は、microSDカードによるオフライン更新への対応前でした。

そのため、次の両方が成立しない状態でした。

- 校内LAN経由のオンライン更新
- microSDカードを使ったオフライン更新

### 実施した例外措置

学校管理職の許可を得た上で、個人所有のスマートフォンによるテザリングへA1 miniだけを一時的に接続し、初回更新を行いました。

ファームウェアを`v01.07.01.00`へ更新した後は、A1 miniを校内LANへ戻しました。テザリングは日常運用には使用していません。

個人回線や管理外ネットワークへの接続は、学校または設置者の情報セキュリティ規程に抵触する可能性があります。

本事例は、学校管理職の許可を得て実施した一時的な例外措置であり、無許可のテザリングを推奨するものではありません。

### 更新後の結果と限界

更新後は、LANモードで接続できました。

ただし、更新前後で完全な対照試験を行ったわけではありません。旧ファームウェアだけが、接続できなかった唯一の原因であったとは断定しません。

### 今後の更新方法

Bambu Lab公式のA1 miniファームウェア履歴によると、`v01.04.00.00`でmicroSDカードからのオフライン更新に対応しています。

今後は、microSDカードを使ったオフライン更新を原則とします。

納入時のファームウェアが`v01.04.00.00`未満である可能性がある場合は、販売事業者へ納入前更新を依頼する方が安全です。

### AMS Liteを接続している場合

他校での確認事例として、納入時のA1シリーズ本体とAMS Liteのファームウェアバージョンに不整合があり、AMS Liteを使用できない事象がありました。

この事例では、AMS Liteを本体へ接続した状態で、本体のファームウェアをmicroSDカードからオフライン更新しました。

更新処理によってAMS Lite側も更新され、完了後は正常に使用できるようになりました。

納入直後にAMS Liteを使用できない場合でも、直ちに機器故障と判断するのではなく、次を確認します。

- A1シリーズ本体とAMS Liteが正しく接続されている
- 本体のファームウェアバージョンを確認できる
- AMS Liteを接続した状態で更新している
- 更新完了後にAMS Liteが本体から認識される
- フィラメントのロードとアンロードができる
- AMS Liteの各スロットを選択できる

この結果は、特定の納入機とファームウェアの組み合わせで確認されたものです。すべてのAMS Liteの不具合が、ファームウェア更新で解消するとは限りません。

更新後も認識しない場合は、配線とコネクターを確認し、販売事業者またはメーカーへ問い合わせる必要があります。

<a id="network-plugin"></a>
## 11. Bambu Studioのネットワークプラグイン

次に止まったのは、3Dプリンタ本体ではなくBambu Studio側でした。

Bambu Studioは、初回起動時にネットワークプラグインを取得します。本事例のPC教室環境では外部サーバーへ接続できずにこの取得へ失敗し、Bambu Studio本体をインストールできていても3Dプリンタ接続機能を正常に利用できませんでした。

PC教室の端末には、外部アクセス、プロキシ、書き込み権限、ユーザー権限などの制約があります。初回起動時に追加コンポーネントを取得するアプリケーションは、インストールが完了していても、その先で止まることがあります。

今回は、PC教室の教員用PCで、Bambu Lab公式Wikiの手順に従ってネットワークプラグインを手動インストールし、Bambu Studioの起動とA1 miniへの接続を確認したうえで、検証済みの設定を多数の生徒用ユーザープロファイルへ展開しました。

固定された授業環境では、初期設定を利用者ごとに行わせると、授業時間の損失と設定差異が増えます。最初の授業で全員が同じ画面へ到達できなければ、モデリングや造形条件の説明へ進めません。

管理側で標準化できる部分は、授業前にそろえておく方が安定します。

公式Wikiの該当ページは、プラグインサーバーへの到達確認と手動対応を説明しています。リンクは[参考資料](references.md)に掲載しています。

<a id="profile-deployment"></a>
## 12. 多数端末・多数ユーザーへのBambu Studio設定展開

### この節の位置付け

ここで説明する構成は、Bambu Labが公式に案内する一括展開手順ではありません。導入時に使用したWindows環境とBambu Studio `v02.04.00.70`で成立した、暫定的かつ非公式な構成例です。

次の意味ではありません。

- 他校へそのまま適用できる
- 配布対象が将来のバージョンでも同じ
- プラグインや設定資産の複製・再配布が常に許可される
- 既存の利用者設定へ上書きしても問題が起きない
- 担当者が変わっても、そのまま引き継げる

実際に展開する場合は、Bambu Studio本体と設定資産のバージョンを一致させ、既存設定をバックアップし、検証用ユーザーで起動から造形まで確認します。プラグインやシステム資産を複製する場合は、利用規約とライセンスの確認が必要です。確認できない場合は、公式の取得手順を優先します。

配布方法、アクセス権、上書き、ロールバックなどの具体的な内部実装は、本記事では公開しません。

この方法は、授業を開始するために不足していた管理機能を補う暫定策です。設定ファイルの構造とバージョン差を理解できる担当者に依存しており、長期的な標準運用や移管可能な手順としては未完成です。

### 保存場所はユーザープロファイル単位

Bambu Studioのネットワークプラグインと設定の一部は、Windowsのアプリケーション共通領域ではなく、各Windowsユーザーのユーザープロファイルに保存されます。

概念的な保存場所は次のとおりです。

```text
Windowsユーザープロファイル
└─ AppData
   └─ Roaming
      └─ BambuStudio
```

1台のWindows PCを複数の生徒が異なるアカウントで使用する環境では、設定の準備もユーザープロファイル単位になります。

設定を利用者ごとに分離すること自体は、履歴、権限、個人設定を分けるPCの設計として妥当です。問題は、その設計と、多数の生徒へ同じ初期状態を一斉に用意する授業運用との間をつなぐ、管理者向けの公式展開方法が不足していたことです。

この負担を避けるだけなら、生徒間でWindowsアカウントを共有する方法も、特定のスライサー専用PCへ操作を集約する方法もあります。ただしその場合は、利用者の識別、データ管理、並列作業、障害時の復旧で別の問題が生じます。本事例では、これらを標準解とはせず、個別アカウントを維持したまま管理者が既定状態を展開できる仕組みを必要条件と考えます。

### 本事例で配布対象とした設定資産

検証用PCでBambu Studioの起動、ネットワークプラグインの動作、A1 miniへのLANモード接続を確認した後、次の設定資産を標準セットとして扱いました。

```text
BambuStudio.conf
plugins/
printers/
system/
user/default/
```

各資産の主な役割は次のとおりです。

| 配布物 | 本事例で確認した主な役割 |
|---|---|
| `plugins/` | ネットワーク機能などの追加コンポーネント |
| `printers/` | A1 miniを含むプリンタ定義 |
| `system/` | Bambu Studioが使用するシステムプロファイル |
| `user/default/` | フィラメントと造形条件の既定設定 |
| `BambuStudio.conf` | 初回起動状態、画面表示、LAN接続などに関係する設定 |

特定の資産が常に必要、または常に不要であるとは断定できません。

### 設定フォルダー全体を配布しない

検証用PCの`BambuStudio`フォルダー全体を、そのまま他の利用者へコピーすることは避けました。

設定フォルダーには、動作に必要な資産だけでなく、履歴、一時ファイル、ログ、キャッシュ、障害解析用ファイル、利用者固有の情報が含まれる可能性があります。

本事例では、次のようなものを配布対象から除外しました。

```text
log/
cache/
ota/
クラッシュダンプ
バックアップファイル
利用履歴
端末固有のパス
個人アカウント情報
```

配布用の標準セットを作成する場合は、必要な設定だけを選び、個人や端末に依存する情報を取り除きます。

### `BambuStudio.conf`のサニタイズ

`BambuStudio.conf`には、初回起動状態や画面表示のほか、最近使用したファイル、ダウンロード先、ウィンドウ位置、利用履歴、接続情報などが保存される場合があります。

設定ファイルから個人情報、履歴、端末固有情報を取り除く処理を、ここではサニタイズと呼びます。

教員用PCや検証用PCの設定ファイルは、そのまま利用者へ配布しません。内容を確認した上で、配布用マスターを作成しました。

本事例では、次のような初期状態に関係する項目を残しました。

```text
firstguide.finish = true
user_mode = simple
```

一方、次の情報は削除対象としました。

```text
最近使用したファイル
最近開いたプロジェクト
ダウンロード先
ウィンドウ位置
画面レイアウト
利用履歴
検証用PC固有のパス
個人アカウント情報
```

設定項目名やファイル構造は、Bambu Studioのバージョンによって変わる可能性があります。設定ファイルを編集する場合は、元ファイルを保存し、検証用ユーザーで起動確認を行います。

### LANモードの認証情報

Bambu Studioの設定には、LANモードで3Dプリンタへ接続するための情報が含まれる場合があります。

アクセスコードなどの認証情報を設定ファイルへ含めるかどうかは、学校や施設の運用に応じて判断します。

少なくとも、次を確認します。

- 設定ファイルを閲覧できる利用者
- 利用者間で共有してよい情報か
- 漏えいした場合にアクセスコードを変更できるか
- 公開資料やスクリーンショットへ写り込まないか
- 3Dプリンタごとに異なる情報をどう管理するか

アクセスコードを設定ファイルへ含めず、使用時に3Dプリンタ本体の画面で確認して入力する方法も選べます。

利便性と認証情報の管理負担を比較して決める必要があります。

### 配布対象を変更した場合の確認

配布対象を変更した場合は、検証用環境で次の一連の操作を確認します。

1. Bambu Studioを起動できる
2. A1 miniをLANモードで追加できる
3. モデルを読み込める
4. スライスできる
5. 送信先3Dプリンタを選択できる
6. 造形データを送信できる
7. 造形を開始できる

### PCではなくユーザー単位で確認する

管理者アカウントや教員アカウントでBambu Studioが動作しても、同じWindows PCを使う生徒アカウントに設定が入っているとは限りません。

確認する単位は、単なるPC台数ではありません。

```text
Windows PC
＋
Windowsユーザープロファイル
```

本事例で確認できた範囲は次のとおりです。

- 対象ユーザープロファイルへの設定資産の配置
- 代表的な生徒アカウントでのBambu Studio起動
- 教員用環境でのLANモード接続と造形
- 実際の授業での利用

全ユーザープロファイルへ設定ファイルを配置したことと、全利用者が実際にプリンタへ接続して造形したことは同じではありません。

### Bambu Studio更新時の再検証

Bambu Studioを更新した後に、以前の配布用設定を検証せず再利用することは避けます。

更新時は、次の順で確認します。

1. 検証用PCを1台だけ更新する
2. Bambu Studioが正常に起動する
3. A1 miniへLANモードで接続できる
4. 3Dモデルを読み込んでスライスできる
5. 造形データをA1 miniへ送信できる
6. 新しいバージョン用の設定資産を確認する
7. 生徒用ユーザープロファイルで起動を確認する

学校の授業環境では、アプリケーション本体と設定資産を、同じ検証済みバージョンの組み合わせで管理する方が安定します。

### 学校向けに必要だと考える公式管理機能

本事例で必要とした管理機能について、利用可能な公式手順を確認できませんでした。学校や研修施設で多数ユーザーを管理するには、少なくとも次の公式機能・文書が必要だと考えます。

- 管理者向けの一括インストール・一括設定手順
- ネットワークプラグインを端末全体へ導入する方法
- ユーザープロファイルごとの初回設定を管理者が事前適用する方法
- 標準の3Dプリンタ・フィラメント・プロセスなどの設定を組織単位で配布する方法
- 授業期間中の更新通知を抑止する方法、または検証済みバージョンを固定する方法
- 更新前後の設定互換性、移行、ロールバックに関する公式文書
- 利用者設定を既定状態へ戻す管理者用リセット手順

ユーザーごとの設定分離を崩すのではなく、その上に管理者による展開・固定・復旧の仕組みを用意することが、共用PC環境との両立に必要です。

<a id="ip-operation"></a>
## 13. DHCP予約を利用できない場合のIPアドレス運用

今回確認したA1 miniのファームウェアと設定画面では、3Dプリンタ本体側に固定IPアドレスを設定する項目を確認できませんでした。

運用上は、ネットワーク側のDHCP予約でMACアドレスとIPアドレスを対応付ける方法が管理しやすいと考えますが、今回使用したアクセスポイントにはDHCP予約機能がなく、既存ネットワークとの関係から別方式も採用できませんでした。

そこで、専用アクセスポイントのDHCP払い出し範囲を必要最小限にしました。3DプリンタのIPアドレスは固定台帳で管理していません。

この設定の目的は、払い出されるアドレス候補を減らし、使用時の確認を単純化することです。同じA1 miniへ常に同じIPアドレスが割り当てられることは保証されません。

DHCP範囲を狭くしても、次の効果はありません。

- IPアドレスの変動を防ぐ
- 不正接続を防ぐ
- 接続機器を認証する
- セキュリティ対策を代替する

具体的な設定は、施設のネットワーク管理担当者と相談し、内部資料として管理する必要があります。

日常運用では、造形前に3Dプリンタの画面で現在のIPアドレスとアクセスコードを確認し、Bambu Studioへ入力します。

<a id="daily-operation"></a>
## 14. 日常運用の基本手順

今回の環境では、3DプリンタのIPアドレスを固定台帳で管理せず、使用時に本体画面で確認します。

基本手順は次のとおりです。

1. 使用する3Dプリンタを決める
2. 3Dプリンタ本体のLANモード画面を開く
3. 現在のIPアドレスとアクセスコードを確認する
4. Bambu Studioで対象3DプリンタのIPアドレスとアクセスコードを入力する
5. 造形データをスライスする
6. 送信先として選択されている3Dプリンタを確認する
7. 造形データを送信する
8. 造形を開始する
9. 初層の定着を確認する
10. 異常があれば操作を続けず、教員または管理者へ知らせる

LANモードのアクセスコードは接続用の認証情報です。公開記事、写真、スクリーンショット、一般共有資料へ写り込ませず、授業や管理に必要な範囲で取り扱います。

この運用は、固定IPアドレスとDHCP予約を利用できない条件下で採用したものです。利用者自身が本体表示と送信先を照合することで、誤送信を防ぎます。

<a id="safety"></a>
## 15. 安全管理

本記事は、3Dプリンタの安全マニュアルや設置者の安全基準を代替するものではありません。

A1 miniは、ホットエンドなどの高温部と可動部が外部から見えるオープン構造です。主な重大リスクとして、高温部への接触による火傷と、可動部への接触・挟まれが考えられます。

本質安全の観点では、高温部や可動部を覆うカバーと、カバーを開いたときに停止するインターロックを備えた構造が望まれます。一方、本事例では、中学生に対して稼働中の本体、ビルドプレート、造形物へ触れないことを明確に指示し、教員が監督する運用を採りました。

授業中だけでなく、造形が続く授業間も教員が同じ教室内に残り、異常時に対応できる状態を維持しました。造形完了後のビルドプレートの取り外しと、異常時の停止操作は教員が担当しました。授業当日の観察の様子は、[初年度実践の「授業中の安全運用」](classroom-practice-2025.md#safety)に記録しています。

学校や施設では、少なくとも次を事前に定める必要があります。

- 造形中の監督者
- 授業終了後も造形が続く場合の扱い
- 完成品とビルドプレートを取り外す担当者
- 異常停止を行う担当者
- 無人運転の可否
- 換気
- 工具の使用
- 材料の保管
- 異常時の連絡と復旧手順

<a id="classroom-practice"></a>
## 16. 授業実践の記録

導入初年度には、中学校3年生4クラス（1クラス約40人、計約160人）を対象として、卒業記念のネームプレートまたはメッセージプレートを製作する授業を行いました。授業ではA1 miniを6台使用しました。

生徒の授業時数は50分 × 3時間（計150分）です。

ただし、授業間および放課後には、教員が未提出データの回収、班別3MFの作成、造形完了後の処理、欠席者・未完者の追加造形を行いました。3MFは、3Dモデルに加えて配置やスライス条件をプロジェクトとして保持できるファイル形式です。

計150分は、実践全体の総作業時間ではありません。

生徒はTinkercadで3Dモデルを作成し、Bambu Studioでスライス結果を確認しました。班の代表者は、A1 miniへLANモードで接続し、送信先を確認してから造形を開始しました。

授業では、3Dプリンタ本体よりも、造形可能なモデルの見分け方、ダウンロードしたファイルの扱い、3Dモデルの提出、教員によるデータ回収が大きな課題になりました。

初年度の授業条件、発生した問題、教員の授業時間外作業は、[中学校3年生160人規模で卒業記念プレートを3Dプリントした初年度実践](classroom-practice-2025.md)にまとめています。

次年度計画は別ページで公開予定です。

<a id="operational-evaluation"></a>
## 17. 初年度の実施と継続・移管を分けて考える

本事例では、全4クラスでモデル作成から造形開始までの工程を実施できました。一方、初回設定、非公式な設定展開、授業時間外のデータ回収と造形処理には、担当教員の作業が必要でした。

したがって、初年度に授業を実施できたことと、次年度以降も同じ方法を継続できること、別の担当者へ移管できることは分けて評価します。

導入時には、本体価格と造形性能だけでなく、次の条件も確認対象になります。

- Bambu Studioを利用できるWindows PC
- 3Dプリンタと通信できるネットワーク
- ファームウェアの更新手段
- ネットワークプラグインの事前導入
- 検証用端末と検証用ユーザーでの動作確認
- 多数のユーザープロファイルへ既定状態を展開する方法
- 複数モデルをまとめる授業時間外作業
- 造形中と授業間の監督
- 更新後の再検証と、担当者変更時の引継ぎ

導入費用には、本体と消耗品だけでなく、端末環境、ネットワーク調整、初期設定、授業準備、監督、保守に必要な人的負担も含まれます。納品の完了と、授業運用の完成は同じではありません。

<a id="administrators"></a>
## 18. 導入を検討・支援する立場の方へ

3Dプリンタは、本体だけで授業利用が成立する機器ではありません。3Dモデル作成、データの受け渡し、スライス、ネットワーク接続、安全管理、消耗品供給、保守がつながって、はじめて授業になります。

この節は、販売・導入支援事業者と、導入を決める側の双方へ向けたものです。導入を決める側とは、教育委員会、学校法人、学校管理職、そしてFabLabや研修施設の施設管理者を指します。確認する工程は共通で、担う役割が違います。

### 実環境で一連の工程を確認する

事業者が持ち込んだ専用端末ではなく、導入先で実際に使用する生徒用端末と学校ネットワークで、次の流れを確認します。

1. 生徒用端末で3Dモデルを作成できる
2. 3DモデルをBambu Studioを使用するPCへ渡せる
3. Bambu Studioでモデルを読み込める
4. 造形条件を設定できる
5. 学校のネットワークから3Dプリンタへ送信できる
6. 安全に造形を監督できる
7. 完成品を生徒へ返却できる
8. 更新後も既定状態を再展開できる
9. 担当者が変わった場合に、必要な確認事項を引き継げる

実環境で再現できない工程があれば、導入前に未解決の条件として整理します。すべてを一人が理解する必要はありません。ただし、端末、ネットワーク、授業、安全、保守を組織内外の担当者で分担できる体制は要ります。

### 販売・導入支援事業者へ

納入前に本体と周辺機器のファームウェアを確認し、可能であれば実環境での動作確認まで支援していただけると、導入直後の停止を減らせます。本事例では、納入時のファームウェアでLANモードのアクセスコードを追加できず、初回更新に例外的な措置が必要になりました。

学校向けには、利用者ごとの設定分離を維持したまま、一括設定、更新制御、設定復旧を行える公式な管理方法も必要です。本事例で行った設定ファイルの展開は、公式手順を確認できなかった部分を補う暫定策でした。

支援の範囲を3Dプリンタ本体に限らず、3Dモデリング環境の構築まで広げていただけると、導入後の管理が軽くなります。生徒アカウントの用意、クラスの作成、テンプレートの配布、書き出したデータのスライサーへの受け渡しまでを実環境で一度通しておけば、学校側は次年度以降その手順をなぞれます。逆にここが未整備のまま納品されると、授業担当者が一人で組み立て直すことになります。

フィラメント使用量、交換部品、保守記録は、稼働状況を把握する補助指標です。ただし、消耗品の使用量自体が教育的成果を示すわけではありません。授業実施回数、参加人数、造形成功率、利用停止期間、教員・支援員の作業時間と併せて評価する必要があります。

### 教育委員会、学校法人、学校管理職、施設管理者へ

事業者の提案に加えて、購入側でも、実際の授業、端末、ネットワーク、教職員の勤務体制、監督方法との適合性を確認する必要があります。実環境での動作確認は、提案・納入条件へ含めておくと確実です。

3Dモデリング環境の選定も、購入側で決める事項です。3Dプリンタの機種が決まっても、生徒に何を学ばせるかで適した3D-CADは変わります。短時間で造形まで到達させるのか、寸法と拘束を使った設計を学ばせるのか、木工作品の部品と木取りを扱うのか。学習目標が違えば、必要な機能も、アカウント運用も、教職員の準備量も変わります。選定の観点は「[学校の3Dモデリング環境をどう選ぶか](3d-modeling-environment-selection.md)」にまとめました。

本事例で使った非公式な設定展開は、詳しい担当者がいることで成立した暫定策でした。共有アカウントや特定のスライサー専用PCへ操作を集約すれば設定の手間は減りますが、利用者の識別と障害時の復旧で別の問題を抱えます。個別アカウントを維持したまま管理者が設定を展開・固定・復旧できる方法を、調達・運用条件として確認することが望まれます。

<a id="evaluation"></a>
### 導入後の評価は稼働状況、学習上の記録、運用持続性に分ける

#### 稼働状況

- 使用回数
- 造形件数
- 消耗品使用量
- 保守記録
- 利用停止期間

#### 学習上の記録

- 授業実施回数
- 参加した生徒数
- 授業の学習目標
- 生徒が自力で行えた工程
- 設計を修正・改善した過程
- スライス結果の確認
- 造形失敗と復旧の記録
- 生徒の振り返り

#### 運用持続性

- 必要となった授業時数
- 教員・支援員の作業
- 再造形件数
- 設定の復旧
- 担当者変更後の継続性

購入台数やフィラメント消費量だけで、導入の成否は判断できません。稼働が続いていることと、その利用が実際の学習へつながっていることは、分けて確認します。

本事例では共通の評価規準による学習効果を測定していないため、中央の群は「教育的成果」ではなく「学習上の記録」としています。

本記事は、単一校の初年度事例を、同様の条件を検討する際の確認材料として公開しています。製品や支援内容を、それぞれの学校の実環境へ合わせるために使ってください。

<a id="summary"></a>
## 19. まとめ

Bambu Lab A1 miniのLANモードは、生徒ごとのBambu Labクラウドアカウントを運用しない選択肢になり得ます。Bambu StudioからA1 miniへの接続と造形データ送信を、校内LAN内で完結させられるためです。

一方で、事前に確認しておくことがあります。

- 2.4 GHz帯Wi-Fi
- スライサー用PCから3DプリンタへのLAN通信
- ファームウェアの更新経路
- Bambu Studioのネットワークプラグイン
- ユーザープロファイル単位の設定
- 認証情報の管理

生徒用iPadでモデルを作成し、Windows PCでスライスする場合は、端末間のファイル受け渡しも授業前の検証対象です。

ユーザーごとに設定を分離すること自体は、PCとして妥当な設計です。学校の共用PC運用で不足していたのは、その分離を保ったまま、管理者が多数ユーザーへ同じ初期状態を展開し、授業期間中のバージョンを管理し、問題時に復旧する公式な仕組みでした。

初年度は、全4クラスでモデル作成から造形までの工程を実施できました。しかし、非公式な設定展開と教員の授業外作業に依存しており、持続可能性と移管可能性は未確認です。

箱を開けた日は、導入の完了日ではありません。詳しい担当者の個別対応に頼らず、個別アカウントを維持したまま同じ授業環境を再現できるか。今後は、その条件まで確かめていきます。
